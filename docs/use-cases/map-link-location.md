# 貼地圖分享連結定位天氣

> 狀態：草稿（2026-09-22）｜對應討論：天氣精確度重新設計（9/18）→ 地圖選點盤點 → 改為展開分享短網址（9/22）

## 機制名稱

貼地圖分享連結定位天氣

## 使用角色

- 行程建立者（在產生器排行程）
- 旅伴（在行程 App 新增或修改景點、住宿）

## 前置條件

- 使用者已在地圖服務中找到要去的地點（業務上例如：Google 地圖 App 或網頁）
- 使用者的裝置可以連線
- 行程 App 的交付模式為進階模式或最低門檻模式皆可

## 使用情境

### 行程建立者（產生器）

- 行程建立者在活動或住宿的地點欄位貼上地圖分享連結
  - 替代：貼的是地名文字 → 機制照樣保存，地點只用於開啟地圖搜尋，不用於天氣，並提示「貼地圖分享連結才會有這個地點的天氣」
- 機制讀出連結指向的地點，顯示地點名稱，讓行程建立者確認
  - 替代：連結沒有指向單一地點（業務上例如：分享的是搜尋結果或路線）→ 機制提示讀不到位置，請改分享單一地點
  - 替代：無法連線或讀取失敗 → 機制提示讀不到位置，保留已貼的連結，稍後可重試
- 替代：行程建立者發現地點不對 → 重新貼上另一個連結，覆蓋原本的地點
- 完成
  - 匯出的行程 App 中，該活動或住宿的天氣以連結指向的地點查詢

### 旅伴（行程 App）

- 旅伴新增景點，填入景點名稱
- 旅伴由機制開啟地圖服務，以景點名稱搜尋，找到正確地點後分享連結，回到行程 App 貼上
  - 替代：旅伴已有地點連結 → 直接貼上
  - 替代：旅伴不貼連結 → 機制照樣保存；該景點沿用當天其他地點的天氣
- 機制讀出連結指向的地點，顯示地點名稱，讓旅伴確認
  - 替代：同產生器的「沒有指向單一地點」「讀取失敗」
- 替代：旅伴在保存後才發現地點不對 → 編輯該景點，重新貼上連結
- 住宿同理：旅伴修改住宿時貼上連結，住宿的天氣以連結地點查詢
- 完成
  - 該景點或住宿的天氣以連結指向的地點查詢
  - 進階模式：地點隨行程同步給其他旅伴；最低門檻模式：只存在旅伴自己的裝置

### 既有行程

- 行程 App 開啟時，找出先前保存、尚未讀出位置的地圖分享連結，逐一讀出位置
- 完成
  - 讀出的位置保存在裝置上，之後開啟不再重讀

## 設計筆記

- 天氣只用使用者明確指定的地點（地圖分享連結或既有的精確座標），不再以地名文字猜測位置。理由：地名猜測可能落在不相干但看似正常的地點（實測「早餐」查到別的城市的餐廳），且程式無法分辨對錯。天氣的精細度設計上是「一天／一個區域」（這天要不要帶雨具、穿多厚），沒有自己地點的景點沿用當天其他地點即可。
- 使用者不需要知道或處理座標。互動只有「分享連結、貼上、看地點名稱確認」，確認用地點名稱而非座標數字。
- 以「分享連結」為主要輸入，因為那是使用者本來就會做的動作；原先規劃的地圖選點（內嵌地圖）因此暫不需要。
- 分享短網址本身不含位置，需由伺服器讀出轉址目標；瀏覽器端受安全限制讀不到。讀取服務只接受地圖分享短網址，只傳送連結、不傳送行程內容。
- 讀取服務設在旅人手帖網站上，所有使用者的行程 App 共用，會消耗網站方的主機額度；因此每個連結只讀一次並保存結果。
