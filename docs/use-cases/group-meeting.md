# 指定對象的集合

> 狀態：草稿（2026-10-05）｜對應討論：分組旅行（各組分頭出發、中途會合、分頭回程）

## 機制名稱

指定對象的集合

## 使用角色

- 發起集合的旅伴
- 集合對象中的旅伴
- 不在集合對象中的旅伴

## 前置條件

- 行程 App 採進階模式（多人同步），集合才能在旅伴之間共用
- 旅伴已在行程 App 選擇自己的成員代號（見[依身分檢視行程](group-trip-view.md)）

## 使用情境

### 發起集合的旅伴

- 旅伴發起集合，填寫集合時間與集合說明
  - 例如：15:00，天文館通電車站前
- 行程 App 預設集合對象為發起者當日日行程的行程對象
  - 例如：11/4 鹿兒島組旅伴發起集合，集合對象預設為鹿兒島組全員；11/8 在全員日行程中發起，預設為全體成員
- 旅伴確認或調整集合對象，可用組別一次勾選，也可逐一勾選成員代號
- 行程 App 送出集合，記錄發起者的成員代號
  - 替代：同一時段已有其他集合進行中 → 兩個集合並存，互不覆蓋
    - 例如：11/4 鹿兒島組 15:00 集合、福岡組 18:00 集合，兩者同時有效
- 旅伴取消自己發起的集合；只有發起者可取消
  - 替代：集合時間已過 → 該集合標示為已過，可由任一集合對象中的旅伴清除
    - 如：發起者手機沒電，已過的集合不會一直留在其他人的畫面上
- 集合發起完成
  - 同步資料庫新增一筆集合紀錄，包含集合時間、集合說明、集合對象、發起者成員代號
  - 集合對象中的旅伴收到集合提醒

### 集合對象中的旅伴

- 旅伴在行程 App 各分頁看到集合提示，包含倒數時間與集合說明
- 集合時間到達時，行程 App 發出集合提醒
  - 例如：倒數歸零時響鈴並閃爍集合提示（現行行為）
- 旅伴同時屬於多個進行中集合的對象時，集合提示依集合時間先後列出

### 不在集合對象中的旅伴

- 旅伴不會收到該集合的集合提示與提醒
- 旅伴在集合分頁可看到所有進行中的集合，並標示各自的集合對象
  - 例如：福岡組旅伴可看到「鹿兒島組 15:00 天文館通」，但不會響鈴

## 設計筆記

- 現行行程 App 只有一個集合欄位（`template-src.html` 的 `setMeeting` 寫入單一路徑），後發起的集合會覆蓋先發起的。分頭期間兩組各自集合是常態，因此「多個集合並存」是本機制必要的一部分，不只是加上「通知誰」。
- 集合對象記錄成員代號而非組別，與[分組行程建立](group-trip-setup.md)的行程對象一致；組別只是勾選捷徑。
- 集合對象的預設值取自發起者當日日行程，讓最常見的情況（只集合自己這組）不需要調整（技巧 7：預設規則是機制，「預設為同組」是由行程資料推得的結果，不寫死組別）。
- 只有發起者可取消（2026-10-05 決定；現行版本任何人都能取消）。發起者以裝置上選擇的成員代號判斷，屬於防誤觸，不是防冒用：沒有登入機制，旅伴可選擇他人的成員代號。現行集合表單的「由誰設定」為自由填寫文字，並記在裝置上（`localStorage` 的 `meetingName`），改為選擇成員代號後即可取代。
- 動詞統一用「發起／取消／清除」集合，提醒統一用「集合提醒」（技巧 2）。
