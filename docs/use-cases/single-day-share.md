# 單日行程分享

> 狀態：草稿（2026-09-13；2026-09-15 修訂：圖卡呈現欄位、分享起點、兩種交付模式）｜對應討論：分享情境腦力激盪

## 機制名稱

單日行程分享

## 使用角色

- 行程建立者
- 旅伴

## 前置條件

- 行程建立者已完成至少一天的行程內容，該日期至少有一個景點
- 行程建立者已在裝置上開啟該份行程的行程 App
- 分享對象使用的通訊軟體可傳送圖片與連結（業務上例如：LINE 群組）

## 使用情境

### 行程建立者

- 行程建立者從要分享的那一天發起分享
  - 替代：該日期沒有任何景點 → 機制提示該日尚無行程內容，不產生分享內容
- 機制依所選日期產生分享內容，包含行程圖卡與行程連結
  - 行程圖卡呈現該日期的日期、當日主題、景點名稱與順序、已填寫的時間、景點補充說明、訂位號碼、住宿名稱與地點、天氣資訊
  - 行程圖卡預設呈現旅伴行動所需的全部欄位，包含訂位號碼、住宿地點等個人資料，因為分享對象是同行旅伴
- 行程建立者確認分享內容
  - 替代：行程建立者調整分享內容的呈現範圍 → 於送出前隱藏特定欄位，可隱藏的欄位可設定（業務上例如：訂位號碼、住宿地點、天氣資訊）
- 行程建立者將分享內容送至分享對象的通訊軟體
  - 行程圖卡供分享對象直接檢視，行程連結供分享對象開啟互動版行程
- 替代：行程建立者在送出後修改了該日行程 → 機制標示該日行程與最近一次分享的版本不同，行程建立者可再次分享
- 分享完成
  - 機制保存該日期最近一次分享的行程版本，作為後續判斷行程是否已變更的依據
  - 已送出的行程連結是否反映後續修改，依行程的交付模式而定
    - 進階模式（多人同步）：行程連結指向同步中的行程，分享對象開啟時看到最新內容
    - 最低門檻模式（行程資料編碼在連結中）：行程連結內含送出當下的行程內容，後續修改不會反映在已送出的連結上

### 旅伴

- 旅伴在通訊軟體收到行程圖卡與行程連結
- 旅伴直接檢視行程圖卡即可掌握當日行程，無需開啟行程連結
- 旅伴開啟行程連結，取得行程圖卡未涵蓋的互動功能（如：地圖導航、停車場查詢）
  - 替代：旅伴在行程連結中調整行程內容 → 依交付模式而定
    - 進階模式：調整同步給行程建立者與其他旅伴
    - 最低門檻模式：調整僅保存在旅伴自己的裝置，不影響行程建立者與其他旅伴
- 檢視完成
  - 旅伴的裝置保存該行程的本機檢視狀態

## 設計筆記

- 機制名稱沒有用「行程小卡」，因為圖卡只是分享內容的其中一種形式，寫進機制名稱會把實作綁死（技巧 1）。內文一律寫「行程連結」而非 QR code，QR 只是連結的呈現方式之一，且在旅伴以手機收圖的情境下無法使用。
- 全文動詞統一用「分享」，未混用傳送／發布／廣播（技巧 2）。旅途中改完行程後的「重新讓旅伴知道」寫成「再次分享」，使其成為同一機制的第二次執行，而非另一個機制。
- 「哪些欄位可隱藏」拆為「機制可設定 + 業務舉例」（技巧 7）。
- 分享從「要分享的那一天」發起（2026-09-15 修訂；初稿原為「機制提供預設分享日期，業務上預設為隔日」）。在該日行程上直接發起，日期即已選定，不需要預設值與日期選擇步驟。
- 前置條件限定在行程 App 發起（2026-09-15 修訂；初稿原含「產生器中的草稿」）。天氣資訊只在行程 App 取得，產生器沒有天氣資料。
- 圖卡預設呈現訂位號碼與住宿地點（2026-09-15 修訂；初稿原寫「不呈現敏感欄位」）。理由：分享對象是同行旅伴，旅伴在櫃台報訂位號碼、前往住宿時用得到；且同時送出的行程連結本就夾帶這些欄位，只從圖卡拿掉並無保護效果。不呈現個人資料的要求屬於[行程展示分享](showcase-share.md)，其對象是不特定的非同行者。圖片可能被轉傳出群組，因此保留「送出前隱藏特定欄位」的替代情境。
- 後置條件明寫行程連結是否反映後續修改（2026-09-15 修訂；初稿只寫「不會反映」）。最低門檻模式的行程資料編碼在網址中，送出當下即固定；進階模式的行程連結指向同步中的網站，開啟時即為最新內容。旅伴調整行程的替代情境同理分兩種模式。寫入 use case 以免設計時誤判連結行為。

## 待確認

2. 最低門檻模式下，旅伴在行程連結中所做的調整僅存在自己裝置，此行為目前未對旅伴說明。是否需要在介面上讓旅伴知道，尚未決定。
