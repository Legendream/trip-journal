# 依身分檢視行程

> 狀態：草稿（2026-10-05）｜對應討論：分組旅行（各組分頭出發、中途會合、分頭回程）

## 機制名稱

依身分檢視行程

## 使用角色

- 旅伴

## 前置條件

- 行程建立者已以產生器產出行程 App（不論有無分組；分組見[分組行程建立](group-trip-setup.md)）
- 旅伴已取得行程連結

## 使用情境

### 旅伴

- 旅伴首次開啟行程 App，從成員名單中選擇自己的成員代號
  - 不論行程有無分組，皆於首次開啟時選擇
  - 替代：開啟者不是旅伴，只想查看行程 → 開啟者略過選擇，行程 App 以全部檢視呈現，並保留選擇成員代號的入口
    - 如：在家的家人收到行程連結
  - 替代：成員名單只有一位成員 → 行程 App 自動選定該成員代號，不詢問
  - 替代：已在使用的行程 App 更新到含本機制的版本 → 旅伴在更新後首次開啟時選擇一次
- 行程 App 記住旅伴選擇的成員代號，之後開啟時直接套用
  - 替代：多人共用同一台裝置，或旅伴選錯 → 旅伴重新選擇成員代號
- 行程 App 預設以個人檢視呈現：只顯示行程對象包含該成員代號的日行程與行程項目
  - 日序依該旅伴實際參與的日行程計算
    - 例如：福岡組旅伴的第 1 天是 11/3，鹿兒島組旅伴的第 1 天是 11/1
  - 「今天」定位到該旅伴當日的日行程
- 旅伴在會合日行程中看到各組的抵達與離開資訊，以及集合地點
  - 例如：11/6「鹿兒島組 10:20 搭機抵達、福岡組 14:00 搭船抵達，16:00 於飯店大廳集合」
  - 會合日行程中，行程對象為其他組的行程項目仍會顯示，並標示所屬組別，讓旅伴知道其他人何時抵達
- 旅伴切換到全部檢視，查看其他組的行程
  - 全部檢視依日期列出所有日行程，同一日期的多個日行程並列，並標示各自的行程對象
  - 旅伴可從全部檢視切回個人檢視
  - 替代：旅伴想確認某位成員目前在哪裡 → 在全部檢視中查看該成員代號當日的日行程
- 檢視完成
  - 旅伴的裝置保存所選成員代號與檢視模式（個人檢視／全部檢視）
  - 記帳的付款人預設與集合的發起者皆取自所選成員代號
  - 檢視模式只影響呈現範圍，不改變行程內容，也不影響其他旅伴

## 設計筆記

- 個人檢視是顯示偏好，不是存取控制。行程資料寫在行程 App 中，持有行程連結者皆可取得全部內容；現行同步資料庫的規則亦為全公開讀寫（`template-src.html` 內的 Firebase 規則設定教學）。若要真正限制可見範圍需另建登入機制，不在本機制範圍。保留全部檢視也讓分頭期間的旅伴能互相照應。
- 選擇的是成員代號而非組別，因為成員可能中途換組（見[分組行程建立](group-trip-setup.md)），以成員代號篩選才能正確呈現；也讓[記帳分擔預設](group-expense-default.md)能預設付款人。
- 全文動詞統一用「檢視」，兩種模式命名為「個人檢視」「全部檢視」（技巧 2、3）。
- 一律於首次開啟時選擇成員代號（2026-10-05 決定），不依有無分組區分。曾考慮「沒分組時等到記帳或集合才詢問」，但那會讓「得知旅伴身分」有兩條程式路徑，記帳與集合都要處理「尚不知身分」的情況；統一詢問只需一條路徑，並可移除現行集合表單中自由填寫的「由誰設定」欄位（記在 `localStorage` 的 `meetingName`）。代價是每位旅伴首次開啟多一次選擇。
- 沒有宣告分組的行程，所有內容的行程對象皆為全體成員，個人檢視與全部檢視結果相同。
