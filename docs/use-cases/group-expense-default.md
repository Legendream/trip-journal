# 記帳分擔預設

> 狀態：草稿（2026-10-05）｜對應討論：分組旅行（各組分頭出發、中途會合、分頭回程）

## 機制名稱

記帳分擔預設

## 使用角色

- 記帳的旅伴

## 前置條件

- 行程 App 採進階模式（多人同步），記帳才能在旅伴之間共用
- 旅伴已在行程 App 選擇自己的成員代號（見[依身分檢視行程](group-trip-view.md)）

## 使用情境

### 記帳的旅伴

- 旅伴新增一筆記帳
- 行程 App 預設付款人為該旅伴的成員代號
  - 替代：實際付款的是其他成員 → 旅伴改選付款人
- 行程 App 預設分擔成員為付款人在記帳日期的日行程行程對象
  - 例如：11/4 鹿兒島組旅伴記一筆晚餐，分擔成員預設為鹿兒島組全員；11/8 記一筆，預設為全體成員
  - 替代：記帳日期不在行程日期內 → 分擔成員預設為全體成員
    - 如：出發前預付的住宿訂金
  - 替代：付款人在記帳日期有多個日行程 → 分擔成員預設為這些日行程行程對象的聯集
- 旅伴確認或調整分擔成員，填寫金額與說明後送出
- 記帳完成
  - 同步資料庫新增一筆記帳紀錄，包含付款人、分擔成員、金額、幣別、說明
  - 結算依各筆記帳紀錄的分擔成員計算，不區分組別，全體成員共用同一份結算

## 設計筆記

- 現行記帳已能逐筆指定分擔成員（`template-src.html` 的 `forWhom`），結算也依此計算（`calcSettlement`），本機制只改預設值，不改結算邏輯。現行預設為全體成員、付款人未預選。
- 不新增記帳日期欄位（2026-10-05 決定）。「記帳日期」以新增記帳當下的裝置日期判斷。補登前幾天的帳時預設會抓到當天的同行者，但分擔成員本來就可以逐一調整，只是預設值不準，不影響結算正確性。現行記帳紀錄只有新增時的 `timestamp`。
- 結算刻意全體共用、不分組：分組旅行的成員最後仍要互相結清，同一份記帳也是讓全體使用同一個行程 App 的理由之一。
