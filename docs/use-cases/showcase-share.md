# 行程展示分享

> 狀態：草稿（2026-09-13）｜對應討論：分享情境腦力激盪

## 機制名稱

行程展示分享

## 使用角色

- 行程建立者
- 觀看者（非同行者，如：親友、社群追蹤者）

## 前置條件

- 行程建立者已完成至少一天的行程內容
- 行程建立者使用的社群平台支援張貼直式圖片（業務上例如：Instagram 限時動態）

## 使用情境

### 行程建立者

- 行程建立者選擇要展示的範圍
  - 機制支援單日與整趟兩種展示範圍
  - 替代：行程尚未全部完成 → 僅展示已有內容的日期
- 機制產生展示圖，採直式版面
  - 版面比例可設定（業務上例如：9:16，以符合限時動態）
  - 展示圖呈現旅程名稱、日期、景點名稱
  - 展示圖不呈現協作用資訊與敏感欄位（如：時間、天氣、訂位號碼、住宿地址、記帳金額）
  - 替代：展示範圍為整趟且天數較多 → 機制改以每日主題呈現，不逐一列出景點
- 機制在展示圖中加入回訪入口，指向工具的建立行程起點
  - 回訪入口的形式可設定（業務上例如：QR code、社群平台的連結貼紙、帳號名稱）
  - 機制至少提供一種同裝置可用的回訪入口形式，因為觀看者多以觀看展示圖的同一台裝置進行後續操作
- 行程建立者將展示圖張貼至社群平台
- 展示完成
  - 展示圖產生後即為獨立圖片檔，機制不保存展示紀錄
  - 展示圖不含行程資料，觀看者無法自展示圖還原完整行程

### 觀看者

- 觀看者在社群平台看到展示圖
- 觀看者透過回訪入口進入工具的建立行程起點
  - 替代：觀看者以同一台裝置觀看展示圖，無法使用需要另一台裝置的回訪入口形式（如：掃描畫面上的 QR code）→ 觀看者改用同裝置可用的回訪入口形式
- 進入完成
  - 觀看者進入的是工具的建立行程起點
  - 觀看者未取得行程建立者的任何行程資料

## 與「單日行程分享」的關鍵差異

同樣是把行程送出去，但這兩個機制的目的相反，設計取捨也相反：

| | 單日行程分享 | 行程展示分享 |
| --- | --- | --- |
| 對象 | 同行旅伴 | 非同行者 |
| 目的 | 協作，讓旅伴知道明天怎麼走 | 展示，並將觀看者導向工具 |
| 資訊密度 | 高（含時間、天氣、訂位號碼、住宿地點） | 低（僅景點名稱） |
| 是否夾帶行程資料 | 是（行程連結內含完整行程） | 否（僅有回訪入口） |
| 回訪入口指向 | 這趟行程 | 工具的建立行程起點 |

## 設計筆記

- 機制名稱沒有用「限動分享」，因為限時動態只是張貼的平台之一，寫進機制名稱會把實作綁死；平台特性改以「直式版面」「連結貼紙」等可設定項目表達（技巧 1、7）。
- 「至少提供一種同裝置可用的回訪入口」這條是機制層級的要求，來自一個具體發現：觀看者無法用同一台手機掃描自己畫面上的 QR code。若只做 QR code，回訪路徑在最主要的情境下是斷的。
- 「展示圖不含行程資料」是刻意的設計決策，不是限制。展示對象包含不特定人，夾帶行程資料會連同旅程細節一併外流。
