# 分組行程建立

> 狀態：草稿（2026-10-05）｜對應討論：分組旅行（各組分頭出發、中途會合、分頭回程）

## 機制名稱

分組行程建立

## 使用角色

- 行程建立者

## 前置條件

- 行程建立者已在產生器開始建立一份行程
- 這趟旅行的旅伴分成兩組以上，各組有部分日期分頭行動、部分日期一起行動
  - 例如：鹿兒島組 11/1 出發、福岡組 11/3 出發，11/6 兩組在屋久島會合，11/12、11/13 分頭回程

## 使用情境

### 行程建立者

- 行程建立者建立成員名單，每位成員以成員代號登記
  - 成員代號由行程建立者自訂，不要求真實姓名（如：小美、阿明、🐱）
- 行程建立者宣告這趟旅行有分組，並建立組別、把成員代號歸入組別
  - 組別名稱可自訂（如：鹿兒島組、福岡組）
  - 組別是勾選成員代號的捷徑，不是行程對象本身
  - 替代：行程建立者沒有宣告分組 → 所有日行程與行程項目的行程對象皆為全體成員，產生器維持現行的單一時間線流程
- 行程建立者匯入行程內容，各組行程可放在同一份文字中
  - 替代：行程建立者手上的各組行程是分開的文件 → 依序匯入，各段開頭標示組別名稱即可（如：「【福岡組】」）
- 產生器依成員名單與組別名稱，判讀每一段行程的行程對象
  - 判讀結果分兩層：日行程的行程對象、行程項目的行程對象
  - 同一日期可以有多個日行程，各自有不同的行程對象
    - 例如：11/3 有「鹿兒島組・霧島」與「福岡組・抵達福岡」兩個日行程
  - 行程項目未另外指定行程對象時，沿用所屬日行程的行程對象
    - 例如：11/6 會合日行程的行程對象是全體成員，其中「鹿兒島組 10:20 抵達」這個行程項目的行程對象只有鹿兒島組
- 行程建立者檢查判讀結果，產生器以組別區分呈現每個日行程與行程項目的行程對象
  - 替代：判讀結果有誤 → 行程建立者直接修改該日行程或行程項目的行程對象，可用組別一次勾選，也可逐一勾選成員代號
  - 替代：某位成員中途改與另一組同行 → 行程建立者把該成員代號加入對應日行程的行程對象，不需要調整組別
    - 例如：阿明原屬福岡組，11/12 改與鹿兒島組多留一天，則 11/12 鹿兒島組的日行程行程對象加入阿明
- 行程建立者為會合日行程與分頭日行程補上各組的交通與抵達、離開時間
- 行程建立者產出行程 App
  - 替代：行程建立者修改已部署行程的成員代號 → 產生器提示既有的記帳與集合紀錄仍以舊成員代號記錄，不會隨之更新
- 分組行程建立完成
  - 產生器輸出一份行程 App，全體成員共用同一個行程連結
  - 每個日行程與行程項目皆記錄行程對象（成員代號的集合）
  - 成員名單記錄每位成員代號所屬的組別

## 設計筆記

- 行程對象記錄成員代號而非組別（技巧 1）。組別只是勾選捷徑，因此成員中途換組時只需調整個別日行程的行程對象，不必有「換組」的額外機制。
- 成員代號建立後沿用，不另設內部編號。行程 App 內無法修改成員名單（`template-src.html` 的 `MEMBERS` 為產出時寫死的常數），唯一會改到成員代號的途徑是回產生器修改後重新部署，以提示處理即可。
- 「同一日期可以有多個日行程」是本機制對現行資料結構最大的變動：現行為一個日期一個日行程。分兩層（日行程／行程項目）的理由是住宿、天氣地點、當日主題都以日行程為單位，兩組人在不同城市時必須分開；而會合日只有抵達段不同，以行程項目區分即可。
- 宣告分組在匯入行程之前（2026-10-05 決定），讓判讀用得上組別名稱與成員代號。宣告預設為「全程一起」，不分組的行程建立者不需多做任何事。
- 匯入只多要求一份分組名單，不要求使用者整理行程格式；判讀錯誤靠檢查步驟修正，不追求判讀全對。
