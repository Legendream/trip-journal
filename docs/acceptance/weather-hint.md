# 讓「沒有天氣」看得見（驗收條件，站①）

> 狀態：已確認（2026-10-17，Claire 確認 App 也要提示、讀不到位置的連結用同一句）。

## 背景

- 天氣只用使用者指定的位置（地圖分享連結或精確定位），不用地名猜（守護清單 G5；2026-10-17 Claire 確認要精確天氣）。
- 問題：一整天的景點都只寫地名時，那天完全沒有天氣，但產生器和 App 都沒有明顯提示。使用者只會覺得「天氣功能不見了」（吉隆坡行程就是這樣）。
- 現況：產生器每個景點旁邊有小字「ⓘ 貼連結才有天氣」，但要一個一個看才知道，整天沒天氣不會特別提醒。
- 這次只做「提示」，**查天氣的規則完全不變**。

## 驗收條件

「這天有位置」的定義：當天至少一個景點或住宿有地圖分享連結或精確定位（跟 App 借用天氣的規則相同）。

| # | 情境 | 預期行為 |
|---|---|---|
| W1 | 產生器步驟 2，某天所有景點、住宿都沒有位置 | 那天的日卡標題列出現「這天沒有天氣」小標籤；收合時也看得到 |
| W2 | W1 的那天貼上任一個景點的地圖連結、讀到地點後 | 標籤消失 |
| W3 | 產生器最後一步（產出分享） | 有一行摘要：「Day 3、Day 5 沒有天氣——貼地圖連結就會有」，附「回去補」可跳到那天；每天都有位置就不顯示 |
| W4 | W3 的提示 | 只是提醒，不會擋下載或分享 |
| W5 | App：某天沒有位置、而且日期在兩週內 | 展開日卡時，第一個景點下方顯示一行灰字「這天的景點沒有貼地圖連結，所以沒有天氣」；不是空白 |
| W6 | App：日期超過兩週 | 跟現在一樣顯示「出發前約兩週才有天氣」，不顯示 W5 的字 |
| W7 | 有位置的天、只寫地名的景點 | 跟現在一樣借用當天其他地點的天氣（不受影響） |
| W8 | 守護清單 G4、G5 | 不變：天氣顯示、載入中 ⏳、只用指定位置 |
| W9 | `build-template.js --check`、`test-group-trip.js` | 都通過 |
