# 驗收條件：貼地圖分享連結定位天氣

> 狀態：已確認（2026-09-22）｜依據：[貼地圖分享連結定位天氣 use case](../use-cases/map-link-location.md)
>
> 開發五站的站①產物。實作、驗證、PR 說明都以本檔為準；站③逐條標記通過／未通過。

## 範圍

- **做**：Google 地圖分享短網址（`maps.app.goo.gl/…`）→ 讀出地點名稱與位置 → 用於天氣；天氣不再用地名文字猜位置
- **涉及**：網站上新增一個讀取短網址的伺服器小程式（Netlify Function）、產生器、行程 App（進階模式、最低門檻 `/v/`、示範頁）
- **不做**：內嵌地圖選點；其他地圖服務（Apple 地圖等）的分享連結

## 設計決定（2026-09-22 討論確認）

| # | 決定 | 理由 |
|---|---|---|
| A | 天氣只用使用者指定的地點：精確座標或讀得出位置的地圖連結；地名文字一律不查天氣 | 9/18 決定（方案 B）：地名猜測會安靜地錯 |
| B | 貼上分享短網址時，由伺服器小程式讀出轉址後的完整網址，從中取出位置與地點名稱 | 實測 `maps.app.goo.gl/12qVVxN4br3P8J2t8` 轉址後含地標座標與「萬家福 林口店」 |
| C | 讀出後把**完整網址**存回地點欄位（取代短網址） | 地圖按鈕照樣可開、位置與名稱之後都能直接讀，不必再呼叫伺服器 |
| D | 舊資料中的短網址在 App 開啟時補讀一次，結果存在裝置上 | 你以前貼的短網址不用重貼 |
| E | 伺服器小程式設在 `trips.claire-cheng.com`，所有人的 App 共用 | 使用者部署的進階版 App 是純靜態上傳，無法自帶伺服器小程式 |
| F | 精確定位區移除「📍 用我目前的位置」按鈕；已經有座標的景點照樣顯示、可清除 | 9/18 決定 GPS 不再當解法推薦；9/22 使用者同意 |

## 驗收條件

### 讀取服務（伺服器小程式）

1. 傳入 `https://maps.app.goo.gl/…` 短網址，回傳轉址後的完整網址
2. 傳入其他任何網址或亂碼，拒絕處理、回傳錯誤，不會代為開啟
3. 只讀取「轉址到哪裡」，不下載目標網頁內容；Google 無回應時幾秒內放棄
4. 不記錄使用者傳來的網址（程式碼中沒有把網址寫進 log）
5. 其他網站（使用者自己部署的進階版 App）也能呼叫
6. 同一條短網址重複請求時，盡量由網站快取直接回答（Netlify 是否支援、如何設定，實作時查官方文件，結果寫進 PR 說明）

### 行程 App：新增／編輯景點（手機）

7. 地點欄位標籤與提示改為引導貼上「Google 地圖分享連結」，並說明貼了才會有這個景點自己的天氣
8. 地點欄位旁有「🔍 到 Google 地圖找」按鈕：已填景點名稱時，用名稱開啟 Google 地圖搜尋；名稱空白時提示先填名稱
9. 貼上分享短網址後，不必按其他按鈕，表單自動顯示「✅ 已定位：〈地點名稱〉」（名稱為一般文字，不是座標或網址編碼）
10. 已定位時附「🗺 在 Google 地圖確認」連結，開啟的是該地點
11. 貼上後讀取中顯示「讀取中…」；讀取失敗（沒網路、網址無效）顯示「⚠️ 讀不到位置」並保留已貼內容，仍可儲存
12. 連結沒有指向單一地點（例如分享的是搜尋結果）時，顯示「⚠️ 這個連結沒有指向單一地點」
13. 重新貼另一個連結會覆蓋前一個，顯示的地點名稱跟著更新
14. 貼上的是 Google 地圖完整網址（電腦網址列那種）時，一樣顯示「已定位」，不需經過伺服器
15. 儲存後，該景點的天氣是連結地點的天氣；進階模式下，另一台裝置看到同一地點與天氣
16. 編輯已存的景點時，表單顯示先前的「已定位：〈地點名稱〉」
17. 不貼連結也能儲存；該景點沒有自己的天氣，改沿用當天其他地點的天氣；「📍 地圖」按鈕仍用名稱搜尋

### 行程 App：住宿

18. 住宿表單的地點欄位具備第 7、9、11、12、13、14 條相同行為（「🔍 到 Google 地圖找」用住宿名稱搜尋）
19. 住宿貼了讀得出位置的連結後，當天沒有自己地點的景點會以住宿（或當天第一個有位置的地點）的天氣為準

### 行程 App：天氣規則

20. 景點只有地名文字（沒有連結、沒有座標）時，不會出現以該地名猜測的天氣
21. 原本「⚠️ 位置可能不精確」的天氣警示不再出現
22. 已經有精確座標（`geo`）的景點，天氣照舊以該座標為準（示範頁有座標的景點天氣不變）
23. 開啟含舊短網址的行程時，App 自動補讀位置，天氣出現；重新整理後不再重新讀取（以網路紀錄確認沒有再次呼叫）
24. 最低門檻模式（`/v/` 連結）與示範頁，第 20–23 條同樣成立

### 產生器（電腦與手機）

25. 活動與住宿的 📍 欄位貼上分享短網址後，自動讀出並顯示「✅ 已定位：〈地點名稱〉」
26. 讀取失敗、連結沒有指向單一地點時，顯示與第 11、12 條相同意義的提示；**不再**對讀不到位置的連結顯示「🔗 連結定位（精準）」
27. 「ⓘ 怎麼修正？」等說明文字改為「Google 地圖 → 分享 → 複製連結 → 貼上」的流程
28. 匯出後的行程 App（進階 zip、`/v/` 連結、預覽）中，這些活動與住宿的天氣以連結地點為準
29. 只填地名文字的活動，提示「貼地圖分享連結才會有這個地點的天氣」

### 不退步

30. 「📍 地圖」「🅿️ 停車」按鈕、單日分享圖卡、行程展示海報照常運作；單日分享圖卡的住宿地點若是網址仍不顯示網址
31. 375px 手機寬度下，新增景點與住宿表單的新元素不被裁切、不溢出
32. 中文輸入法選字時按 Enter 不會誤送出表單（沿用既有防護）
33. `node scripts/build-template.js --check` 通過；瀏覽器 console 無錯誤

### 部署後（合併後在正式站確認）

34. 在 `trips.claire-cheng.com` 的示範頁與 `/v/` 連結上，貼短網址的流程實際可用
35. 使用者自己部署的進階版 App 需重新產生、重新部署才會套用；PR 說明寫明這點
