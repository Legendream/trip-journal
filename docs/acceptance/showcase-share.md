# 驗收條件：行程展示分享（第一批）

> 狀態：草稿，待確認｜依據：[行程展示分享 use case](../use-cases/showcase-share.md)
>
> 開發五站的站①產物。機制名稱（文件內部用語）維持「行程展示分享」；介面文案一律用
> 「行程海報」——「展示圖」對使用者來說看不出用途，「海報」是社群分享圖的通用說法，
> 一看就懂要拿去貼出去。2026-09-15 經腦力激盪補上照片／一句話／Day X 共 N 天／
> 滿版漸層背景，並修正「住宿名稱」不應排除（use case 只排除住宿**地址**）。

## 範圍

- **做**：行程 App 內產生一張直式（9:16）行程海報，給非同行者看（例如 IG 限動的追蹤者），
  可選「單日」或「整趟」範圍，海報上不含協作用資訊或個資，附回訪入口導回旅人手帖首頁
- **兩條路徑資訊量不同**（單日可加照片／一句話，整趟不行，見下方「使用路徑」）
- **只在行程 App**：`template-src.html` 建置出的 App（使用者部署的 App、`/v/` 分享連結、
  示範頁 `trip-app-v2/`）。產生器不做（同單日行程分享的前例）
- **不做**：保存展示紀錄（use case 已寫明機制不保存）；不支援自訂版面比例（先固定 9:16）；
  整趟模式不支援照片／一句話；不支援天氣（已跟使用者確認跳過）

## 使用路徑

**路徑 A・單日模式**
1. 選「單日」→ 選是哪一天（該日沒有任何景點時不能選/提示「該日尚無行程內容」）
2. 可選：輸入一句話（≤20 字，產生海報當下才打，不存進行程資料）
3. 可選：選一張照片（從裝置相簿選，產生海報當下才選，不存進行程資料）
4. 預覽（有照片＝上圖下卡版型；沒照片＝整張主題色滿版漸層）→ 確認送出

**路徑 B・整趟模式**
1. 選「整趟」（整趟所有日期都沒有任何景點時提示「行程尚無內容」，不產生海報）
2. 不提供照片／一句話欄位——固定是每日主題清單＋整張主題色滿版漸層
3. 預覽 → 確認送出

## 設計決定（2026-09-15 確認，含腦力激盪補充）

| # | 決定 | 理由 |
|---|---|---|
| J | 觸發入口獨立於單日行程分享，放在行程頁內容區最上方（Day 1 卡片之前），不掛在日卡上 | 兩種分享對象、資訊量、連結行為完全不同，混在日卡上會讓使用者分不清「這是要給旅伴看還是要曬出去」；App 固定 header 已經很滿，新入口放在會捲動的內容區最上方，不動 header |
| K | 機制名稱維持「行程展示分享」，介面文案（按鈕、入口標籤）一律用「行程海報」／「產生海報」 | 「展示圖」不具體，「海報」直接對應「做出來要分享的圖」，使用者一看就懂用途 |
| L | 整趟模式不設天數門檻，統一用「每日主題」呈現（日期＋emoji＋主題，一天一行），不逐一列景點；畫布固定 9:16，天數多時每行字級自動縮小以塞進固定高度 | 天數門檻沒有明確依據、會增加一條要解釋的邏輯；固定用「每日主題」讓版面可預期。2026-09-15 修正：原訂「高度隨天數增加」跟決定 O 的「版面比例固定 9:16」互相矛盾（高度變動則寬高比不可能固定），改為畫布尺寸永遠固定、字級隨天數自動縮小，9:16 對 IG 限動的承諾才成立 |
| M | 單日模式列出當天全部景點名稱（依 App 畫面上的順序）與住宿名稱，不列時間、補充說明、訂位號碼、住宿地址 | 比單日行程分享（給旅伴）資訊量低很多，符合「對象是非同行者」的定位；住宿**名稱**不是 use case 排除的欄位（只排除地址），且是常見的炫耀素材（JTBD：彰顯身份／生活風格），修正先前草稿誤排除 |
| N | 回訪入口同時顯示文字網址（旅人手帖首頁）＋ QR code；兩者皆為圖片上的靜態內容，不可點擊 | use case 明講「觀看者無法用同一台手機掃描自己畫面上的 QR code」，純 QR 會讓最常見情境（用同一支手機看限動）斷路；文字網址是唯一在任何情境都能用的形式。圖片本質上無法內嵌可點擊連結，真正的可點擊入口（如 IG 連結貼紙）要靠使用者匯入海報後自行在社群平台加上，不在本機制範圍 |
| O | 版面比例固定 9:16（直式） | 對應 IG 限動等直式版位；use case 業務舉例已寫 9:16，先不做成可設定項目 |
| P | 不呈現協作／敏感欄位：時間、補充說明、天氣、訂位號碼、住宿地址、記帳金額 | use case 明文規定（僅列住宿**地址**，非名稱）；展示對象是不特定人 |
| Q | 送出方式延用單日行程分享已驗證的做法：系統分享面板優先，不支援則下載圖片 | 同一套機制在同一個 App 裡，使用者不需要學兩套操作；canvas 產圖＋`navigator.share`／下載備援已經測過可行 |
| R | 背景預設為整張主題色滿版漸層（不是只有一條 header），與單日行程分享的「白底＋粉色 header」圖卡風格區隔 | 行程海報定位是「拿去炫耀、給人看的東西」，滿版漸層視覺上更像一張海報而不是 App 截圖，跟單日行程分享的資訊型圖卡做出區隔 |
| S | 單日模式可選加一張使用者照片（上圖下卡版型：照片佔上半部、下半部維持主題色卡片放文字），選填、不選則維持整張漸層 | JTBD 裡「純粹視覺美感」是唯一純文字排版完全補不了的動機，IG 限動本質是圖片為王；上圖下卡確保文字永遠疊在純色卡片上，不受照片亮暗影響可讀性 |
| T | 照片不存進行程資料，只在產生海報當下選取、用於這次繪製，用完即丟；重用既有的 `compressImage()` 壓縮邏輯（購物清單照片已用同一套） | 不用處理「要不要同步給旅伴」「存在哪」等問題，工程量也小；避免新增資料欄位與同步邏輯 |
| U | 單日模式可選加一句話（≤20 字），同樣是產生海報當下才輸入、不存進行程資料 | 補足「氛圍感染力／自我記錄」的 JTBD，讓海報有使用者自己的溫度，不只是資料清單 |
| V | 單日模式標題加註「Day X／共 N 天」；整趟模式因本來就列出所有天數，不需要這個標註 | 補「炫耀收集／成就感」的 JTBD（里程碑感），`DAYS.length` 本來就有資料，成本低 |
| W | 照片／一句話只在單日模式提供，整趟模式不提供 | 整趟模式若也要選照片，會多一個「用哪一天的照片代表整趟」的新問題，範圍會擴大；先讓整趟模式維持單純的每日主題清單 |

## 驗收條件

### 發起

1. 行程頁內容區最上方（Day 1 卡片之前）有「🖼️ 製作行程海報」入口，任何時候都看得到，不需要先展開某一天
2. 點入口後可選「單日」或「整趟」範圍
3. 選「單日」時可選要展示哪一天；該日沒有任何景點時提示「該日尚無行程內容」，不產生海報
4. 選「整趟」時，若整趟行程完全沒有任何一天有景點，提示「行程尚無內容」，不產生海報
5. 選「整趟」但只有部分日期有內容時，海報只列出「有內容」的日期（use case 替代情境：僅展示已有內容的日期）

### 海報內容（單日範圍）

6. 呈現：旅程名稱、「Day X／共 N 天」、日期（星期）、當日主題、當天全部景點名稱（依 App 畫面上的順序）、住宿名稱（若有）
7. 不呈現：時間、補充說明、訂位號碼、住宿地址、天氣、記帳金額
8. 可選填一句話（上限 20 字），填了會出現在海報上；不填則不出現該欄位、版面不留空白
9. 可選一張照片；選了套用「上圖下卡」版型（照片佔上半部、文字內容在下半部主題色卡片）；不選則整張維持主題色滿版漸層
10. 照片與一句話都只在產生這次海報時使用，不會寫回行程資料、不會同步給旅伴看見
11. 回訪入口：文字網址（旅人手帖首頁）＋ QR code 同時顯示

### 海報內容（整趟範圍）

12. 呈現：旅程名稱、總天數、每一天的日期＋emoji＋主題（一天一行），不逐一列出景點
13. 不提供照片與一句話欄位；整張維持主題色滿版漸層背景
14. 天數再多（例如 10 天以上），海報畫布尺寸不變（維持 9:16），仍維持一天一行、不換算成別的呈現方式，改以字級自動縮小塞進固定高度，文字仍可閱讀
15. 回訪入口同第 11 條

### 版面

16. 整體版面比例為 9:16（直式）
17. 中文、emoji、很長的旅程名稱／主題／一句話，不會超出海報邊界或被裁掉一半的字
18. 示範頁（`trip-app-v2/`）也能使用本功能

### 送出

19. 支援分享圖片的手機瀏覽器（iOS Safari、Android Chrome），按分享會跳出系統分享面板
20. 不支援分享圖片的瀏覽器，改為下載海報圖片

## 驗證方式備註

- 第 19 條需要實機（iPhone／Android），由使用者實測；Claude 可先用瀏覽器與 iOS 模擬器驗證其餘條件
- 第 18 條依「宣告修好前要驗證到部署站」的教訓，以部署後的示範頁為準
