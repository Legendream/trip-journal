# 吉隆坡旅行：順便測試清單

> 2026-10-12 建立。用途：旅行中順手測、順手記，回來後依結果決定要不要開修正。
> 對應的程式改動：PR #8（PWA 身分分開、住宿狀態與多晚、視覺減量）與先前的分組旅行／集合提醒。

## 怎麼記

- 每項測完在「結果」欄填 ✅（符合預期）、❌（不符）、➖（沒測／不適用）。
- 「備註」欄寫：**用什麼手機＋瀏覽器**（例：Pixel 8／Chrome、iPhone 15／Safari）、看到什麼、❌ 時截圖並寫檔名。
- 測前先確認拿到的是新版：用瀏覽器重新整理行程頁一次（舊版快取是已知狀況，見 B6）。
- 一個項目失敗不用停下來，繼續測下一項就好。

## A. 兩個行程可以各自安裝成 App（最優先）

背景：以前所有分享行程都被當成同一個 App，只能裝一個。現在每個行程是獨立的 App。**需要兩個不同的分享連結**（吉隆坡＋任何一個別的行程，舊行程也行）。

| # | 怎麼測 | 預期 | 結果 | 備註 |
|---|---|---|---|---|
| A1 | Android Chrome：開吉隆坡連結 → 右上 ⋮ → 「安裝應用程式」或「加到主畫面」 | 有出現安裝選項，安裝成功 | | |
| A2 | 同一支手機：開另一個行程連結 → 同樣安裝 | 也能安裝，**不會**說「已安裝」或蓋掉前一個 | | |
| A3 | 回到主畫面，兩個圖示各點一次 | 吉隆坡圖示進吉隆坡；另一個圖示進另一個行程，不會兩個都進同一個 | | |
| A4 | iPhone Safari：開連結 → 分享 → 加入主畫面（兩個行程各做一次） | 兩個圖示各進各的行程，跟以前一樣沒有變差 | | |
| A5 | 如果手機以前就裝過舊版行程 App：點開看看 | 預期還是舊身分；**刪掉重裝**後才會換成新的。記下它的實際表現就好 | | |

## B. 住宿：未訂、複製到多天、套用到同一間

用吉隆坡行程裡的住宿實際操作。需要行程有開啟 Firebase 同步（可編輯）才看得到新增／編輯按鈕。

| # | 怎麼測 | 預期 | 結果 | 備註 |
|---|---|---|---|---|
| B1 | 某天「新增住宿」→ 選「還沒訂」→ 名稱留空 → 儲存 | 存得進去；該天住宿列整塊有底色、寫「住宿未訂」；日卡標題列（收合時也看得到）有「住宿未訂」小標籤 | | |
| B2 | 編輯那筆 → 改選「已訂」但**不填名稱** → 儲存 | 跳提示要填名稱，沒存進去；填名稱後存得進去，標記消失，出現「未付款」徽章 | | |
| B3 | 住宿列右下角「⋯」→「複製到其他天」→ 勾兩個以上的日期 → 確認 | 勾的每一天都出現同一間住宿，各自是獨立一張 | | |
| B4 | 同一間住在 3 晚，編輯其中一晚、只改備註 → 表單下方「同時套用到」勾選其他晚（名稱相同的晚會預設勾好）→ 儲存 | 勾到的晚備註也一起改；只更新這次改動的欄位，其他欄位不受影響；沒勾的晚不變 | | |
| B5 | 刪掉一筆未訂的住宿 → 點出現的「復原」 | 復原後仍是未訂 | | |
| B6 | （需要兩支手機，且行程連到同一個 Firebase）A 手機把某晚改成未訂，看 B 手機 | B 手機住宿列與標題列標記**自動跟著變**。記下大約幾秒 | | |
| B7 | （選做）請旅伴先**不要**重新整理，用舊版開行程 | 未訂的住宿可能顯示成沒有名稱的「現場付」→ 這是已知狀況，重新整理後就正常。記下是否真的發生 | | |
| B8 | 整趟海報／單日小卡裡看住宿 | 未訂的住宿不會出現在圖片上 | | |

## C. AI 整理草稿時的住宿判斷

背景：提示詞新增了住宿規則，還沒真的用 AI 跑過。需要產生器的「複製整理指令」＋任何一個 AI（Gemini／ChatGPT／Claude 皆可）。

做法：寫一份簡短草稿，**四種情況各放一天**，貼進 AI，把回傳的 JSON 貼回產生器匯入，看每一天的住宿。

草稿可以這樣寫（日期照你的行程改）：

```
D1：Hotel A，已付清
D2：Hotel B（還沒訂，要再比價）
D3：Hotel C，沒寫付款狀況
D4：沒提到住宿
```

| # | 看什麼 | 預期 | 結果 | 備註 |
|---|---|---|---|---|
| C1 | D2「還沒訂」 | 匯入後該天是「住宿未訂」 | | |
| C2 | D3 有飯店、沒寫付款 | 顯示「未付款」，**不是**未訂 | | |
| C3 | D4 完全沒提 | 這天沒有住宿（不是空白的未訂） | | |
| C4 | D1 已付清 | 顯示「已付清」 | | |
| C5 | 用的是哪個 AI | 記下 AI 名稱與版本 | | |

## D. 視覺：實機看看清不清楚

背景：拿掉了按鈕與標題上的裝飾 emoji，並把四處文字加深。請在**實際使用情境**看，尤其是戶外陽光下。

| # | 怎麼測 | 預期 | 結果 | 備註 |
|---|---|---|---|---|
| D1 | 行程頁：日卡內的「地圖」「停車」「編輯」「新增景點」按鈕 | 只有文字、沒有多餘空白、沒有被切掉 | | |
| D2 | 日卡**收合**時看標題列右側；點開後再看 | 收合：右側有主題 emoji；展開：emoji 不見，右邊箭頭位置沒有跳動 | | |
| D3 | 戶外／亮處看行程時間標籤（例如 08:30 那個小色塊） | 文字看得清楚，不用瞇眼 | | |
| D4 | 設一筆集合，看畫面上方的橘色橫幅與「送出通知」按鈕 | 深色字清楚可讀 | | |
| D5 | 用你吉隆坡行程的主題色，整體看一遍 | 沒有哪個地方看起來「少了什麼」或不知道按鈕是做什麼的。記下任何覺得怪的地方 | | |

## E. 集合提醒（真實 Firebase，包 5）

背景：只用模擬後端驗證過，系統通知排程無法在自動測試裡驗。**需要兩支手機、連到同一個 Firebase。**

| # | 怎麼測 | 預期 | 結果 | 備註 |
|---|---|---|---|---|
| E1 | 手機 A 設集合：時間設在 5 分鐘後、備註寫地點、通知「全員」 | 手機 B 在幾秒內出現橘色橫幅與倒數。記下延遲秒數 | | |
| E2 | 同一筆，手機 B 的行程頁**開著**等到時間 | 響鈴＋震動（Android）。iPhone 記下有沒有響 | | |
| E3 | 時間到時手機**鎖屏**或 App 在背景 | 記下有沒有系統通知（已知：頁面要開著才保證會響，這項是確認實際情況） | | |
| E4 | 通知對象選「某一組」或「自己選」 | 只有被選到的人看到橫幅；沒被選到的人看不到 | | |
| E5 | 發起人按「更新時間」、改一個新時間 | 其他人的橫幅倒數跟著新時間 | | |
| E6 | 非發起人試試看取消那筆集合 | 預期：不能取消（發起者欄位有值時只有發起人能取消）。記下實際 | | |
| E7 | 集合時間過了 30 分鐘後，不重新整理 | 橫幅與集合分頁的那筆自動收起 | | |

## F. 分組旅行（**只有吉隆坡行程有分組才測**）

前四項是原型的真人可用性測試，**不要先提示旅伴怎麼用**，給他們手機、說「請找出『你自己這幾天要去哪』」，觀察卡在哪。

| # | 怎麼測 | 預期／要觀察 | 結果 | 備註 |
|---|---|---|---|---|
| F1 | 旅伴第一次開啟 | 看得懂「你是誰」要選自己嗎？選完有沒有看到自己的行程 | | |
| F2 | 請旅伴在「我的行程」展開一張大家會合的日卡 | 收合時看不看得出裡面有別組的資訊（目前推論看不出來，這項是確認） | | |
| F3 | 請旅伴「把阿某加進這一天的這一組」（或換卡） | 找不找得到「自己選」；找了多久、點了哪裡 | | |
| F4 | 請旅伴解釋「我的行程」跟「全部」差在哪 | 能不能講出來；為什麼有些天有組名標籤、有些沒有 | | |
| F5 | 記一筆帳，付款人與分擔對象選別人 | 結算頁數字對得上；舊名字對不上時有黃色提醒 | | |
