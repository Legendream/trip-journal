# 分組旅行：AI 提示詞與資料格式（草稿）

> 2026-10-06。對應 PROGRESS.md 下一步 1。**提示詞 v3 已通過實測（第 8 節）**，尚未改程式；這份是要放進 `generator/generator-app.js` 的內容與規則。
> 實測工具在 `ai-test/`，用法見最後一節。

## 1. 原則

- **沒分組不動提示詞**（規則 7）：使用者選「全程一起」時，`buildPrompt()` 產出的文字跟現在一字不差。分組段落只在選了「有分頭」且至少填了一組時才插入。
- **組別由產生器擁有，AI 只引用**：AI 回傳的 JSON 不含 `groups`；組別以 D1 填的為準。AI 用了設定外的名字 → A-1。
- **AI 用名字，產生器存 id**：AI 只會寫組名和代號；匯入時才換成成員 id 清單（decisions 第 1 節）。
- **一個欄位 `with` 解決三層**：日卡、活動、住宿共用同一種寫法，AI 好學、檢查好寫。

## 2. 插入提示詞的段落

插在 `PARSE_PROMPT` 的「JSON Schema（嚴格遵守）：」之前。`{分組清單}` 由 D1 的輸入產生，一組一行。實際使用的完整文字以 `ai-test/group-section.txt` 為準，下面是規則部分。

```
分組（使用者已設定，只能用這些組名與代號，不要新增或改寫）：
{分組清單}
例：
- 鹿兒島組：小貓、阿熊
- 福岡組：小魚、阿鹿

分組規則：
- members 只列上面的代號，name 照抄
- 同一天兩組在不同地方：拆成兩筆 days，date、day 相同，各自填 with、theme、emoji、hotel、acts
- 全員一起的日子：一筆 days，不填 with
- 只有部分人在旅途中的日子（還沒出發、已經離開）：只建那些人的卡，with 填他們的組名
- 會合日、分開日：一筆全員卡；只屬於某組的活動，在那筆活動填 with
- with 是陣列，只能放上面的組名或代號；整組同行寫組名，不要拆成組員；跨組或單獨行動才列代號
- 活動沒填 with = 跟這張卡同一批人
- day = 全團第幾天，從草稿最早的日期算起；同一天的兩張卡 day 相同
- 草稿裡的組名寫法不同（例：鹿兒島團、鹿組），對應到上面最接近的組名
- 草稿沒寫清楚是誰，或你是推測的：在那筆加 "unsure": true；不要為了填滿而猜
- 各組住不同地方時，hotels 也加 with
```

## 3. Schema 增加的欄位

只列新增部分，其餘照現有 schema。現有 schema 不改；分組段落末尾附一段含 `with` 的 days 範例（見 `ai-test/group-section.txt`），用中性的 A組／B組，避免 AI 抄到範例行程的內容。

```json
{
  "members": [{ "name": "小貓", "avatar": "🐱" }],
  "days": [
    {
      "day": 3, "date": "11/3", "wd": "二", "theme": "霧島神宮", "emoji": "⛩️",
      "with": ["鹿兒島組"],
      "acts": [
        { "icon": "⛩️", "name": "霧島神宮", "map": "霧島神宮" }
      ]
    },
    {
      "day": 6, "date": "11/6", "wd": "五", "theme": "屋久島會合", "emoji": "🏝️",
      "acts": [
        { "icon": "✈️", "name": "搭機抵達屋久島", "time": "10:20", "with": ["鹿兒島組"] },
        { "icon": "⛴️", "name": "搭船抵達屋久島", "time": "14:00", "with": ["福岡組"] },
        { "icon": "🏨", "name": "飯店大廳集合", "time": "16:00" }
      ]
    },
    {
      "day": 4, "date": "11/4", "wd": "三", "theme": "太宰府", "emoji": "⛩️",
      "with": ["福岡組", "阿熊"], "unsure": true,
      "acts": []
    }
  ],
  "hotels": [
    { "nights": ["11/3"], "name": "…", "with": ["福岡組"] }
  ]
}
```

| 欄位 | 位置 | 值 | 沒填代表 |
|---|---|---|---|
| `with` | 日卡 | 組名或代號的陣列 | 全員 |
| `with` | 活動 | 同上 | 跟日卡相同 |
| `with` | hotels 項目 | 同上 | 全員 |
| `with` | 日卡的 hotel、flight | 同上（全員卡上只屬於部分人時用，例：分開日） | 跟日卡相同 |
| `unsure` | 日卡、活動 | `true` | 有把握 |

## 4. 匯入時的轉換（`applyParsedData`）

1. `with` 每個字串：是組名 → 展開成該組成員；是代號 → 該成員；都不是 → 保留原字串並標 A-1。
2. 展開後存成員 id 清單（去重）。名單 = 全員 → 存空值；活動名單 = 日卡名單 → 存空值（沿用）。
3. `unsure` 只給判讀提醒用（A-5），不輸出到行程 App。
4. 日卡、活動、集合不存組名（decisions 第 1 節）；顯示時由名單反推標籤。
5. 同日多卡排序：依 D1 組別順序；全員卡排最前。

## 5. 判讀提醒的計算定義

| 編號 | 計算方式 |
|---|---|
| A-1 | `with` 裡有字串對不到組名或代號 |
| A-2 | 某成員在同一 date 的兩張以上卡的名單裡 |
| A-3 | 某成員在**自己第一張卡到最後一張卡之間**，某日期沒有任何卡包含他 |
| A-4 | 全員卡的前一天或後一天，有人不在全員卡（= 會合日或分開日）；此卡中某組沒有任何一筆活動的名單恰好等於該組 |
| A-5 | 日卡或活動有 `unsure: true` |

**建議修改 decisions 第 3 節 A-3 的條件**：原文「某人在行程期間某天沒有卡」，若「行程期間」指全團頭尾，範例裡福岡組 11/1–2、鹿兒島組以外的人 11/13 都會誤報。改成「自己第一張卡到最後一張卡之間」。

## 6. 尚未決定（需要 Claire 拍板）

1. **成員 id 從哪來**（已定案，採建議做法，見 decisions 第 1 節）：記帳的 `payer` 現在存名字，M-2 也說「改代號後，舊的記帳不會跟著改」。若成員改用 id，記帳要不要一起改存 id？這會牽動下一步 3（舊行程相容）。建議：產生器內部用 id，匯出時先維持名字當 key，記帳不動；等 Firebase 路徑（下一步 2）一起處理。
2. **`restaurants` 用 day 編號當 key**：同一天兩張卡時分不出屬於哪組。現有提示詞不要求 AI 產餐廳，所以不影響這一步；手動或備份匯入時才會遇到，列入下一步 3。
3. **`weatherLocs` 以日期為 key**：兩組同日不同城市時，現有格式本來就能放多個地點，但 App 不知道哪個地點屬於哪張卡。列入下一步 3。

## 7. 實測方法

`ai-test/` 內容：

| 檔案 | 用途 |
|---|---|
| draft.txt | 範例草稿（brief 的鹿兒島／福岡／屋久島行程，寫成隨手記的樣子） |
| groups.json | D1 填的組別 |
| group-section.txt | 插入提示詞的分組段落 |
| build-prompt.js | 從 generator-app.js 讀現有 PARSE_PROMPT，插入分組段落與草稿，產出 prompt.txt |
| prompt.txt | 組好的完整提示詞，直接貼給 AI |
| expected.json | 正確答案的判準 |
| reference.json | 手寫的理想輸出，check.js 對它應為全對、只有 A-5 |
| check.js | 跑判讀提醒並比對 expected.json |

改了 group-section.txt 或 draft.txt 後，先跑 `node build-prompt.js` 重產 prompt.txt。

1. 把 `ai-test/prompt.txt` 整段貼給 AI（ChatGPT、Gemini、Claude 各試一次），它已經是「現有提示詞＋分組段落＋範例草稿」組好的版本。
2. 把 AI 回的 JSON 存成 `ai-test/out-<AI名稱>.json`。
3. 在 trip-journal 資料夾執行：`node docs/design-handoff/group-trip/ai-test/check.js docs/design-handoff/group-trip/ai-test/out-<AI名稱>.json`
4. 腳本會列出：判讀提醒 A-1～A-5 觸發了哪些、與 `expected.json` 比對的對錯。

範例草稿刻意放了四個陷阱：組名寫法不同（鹿兒島團）、阿熊 11/4 未定、只有一組在旅途中的頭尾日、會合日與分開日的分組活動。
