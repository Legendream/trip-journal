## 1. 資料格式（定案）

### 1.1 匯出設定檔（`collectConfig()`）

所有行程：

```
members: [{ id, name, avatar }]        ← 一律帶 id
```

有分組時（`activeGroups().length > 0`）另外多出：

```
groups: [{ id, name, memberIds }]      ← 陣列順序 = 組別順序
days:   [{ id, day, date, …, with: [成員id],
           acts:  [{ id, …, with: [成員id] }],
           hotel: { …, with: [成員id] } }]
hotels: [{ …, with: [成員id] }]
```

- `with` 沒有或空陣列：日卡 = 全員；活動、日卡的 hotel = 跟日卡相同；`hotels[]` = 全員。
- 航班匯出時已併進 `acts`（`toLegacyDay()` 現行行為），它的 `with` 寫在那筆活動上。
- 不輸出 `unsure`、`withUnknown`、`state.dismissedAlerts`。
- 沒分組時不輸出 `groups`、日卡 `id`、任何 `with`。與改前的差異只有 `members[].id`。

### 1.2 還原（`importLoadedConfig()`）

- 設定檔有 `groups`：直接採用，`state.splitUp = true`；成員 id、日卡 id、各層 `with` 原樣保留。
- 設定檔沒有 `groups`：維持現行行為（步驟 1 已填的組別用名字對上載入的成員）。
- 成員沒有 id（舊檔）：照現行 `ensureMemberIds()` 當場補發。
- 「匯出進度」備份檔本來就存整包 state，不必改。

### 1.3 App 內的識別

| 項目 | 規則 |
|---|---|
| 成員 id | `m.id`；設定檔沒有 id 時用 `m.name` 代替（舊分享連結、`scripts/demo-config.json`） |
| 有沒有分組 | `_CFG.groups` 是非空陣列 |
| 卡片 key | 有分組用 `d.id`；沒分組用 `d.day`（與現行相同，已上線行程的資料不受影響） |
| 舊資料備援 | 分組行程讀取以卡片為 key 的資料時，若用 `d.id` 找不到、且那個 `day` 只有一張卡，改用 `d.day` 找。旅伴新增的景點只有 `day` 沒有卡片 id 時，歸到那天的第一張卡 |
| 標籤反推 | 名單 = 全員 → 不加標籤；= 某組 → 組名標籤；其他 → 成員頭像。與 `generator/group-trip.js` 的 `describeList()`、`groupTagStyle()`、`deepTagColor()` 同一套 |

`group-trip.js` 的這幾個純函式在 App 裡也要用。App 是單一 HTML，做法由實作者決定（建置時從 `group-trip.js` 帶入，或複製一份），但必須有測試保證兩邊結果一致。

### 1.4 存在手機上的資料（localStorage，包 4）

| key | 內容 |
|---|---|
| `<prefix>-me-v1` | 成員 id；`"none"` = 我只是看看；沒有這個 key = 還沒問過 |
| `<prefix>-view-v1` | `"mine"` 或 `"all"` |
| `<prefix>-overrides-v1` | `{ <成員id>: { <day>: <卡片id> } }`（換卡，基本版） |

### 1.5 Firebase（包 5）

Firebase 規則是整個 `<prefix>` 開放讀寫（`generator-app.js` 的規則產生處），新路徑不必改規則。

| 路徑 | 內容 |
|---|---|
| `<prefix>/meetings/<key>` | `{ time, message, setBy: 成員id 或 "", setByName, notify: [成員id]（沒有 = 全員）, setAt }`。所有行程共用，可多筆並存 |
| `<prefix>/meeting` | 舊的單一集合。只讀不寫：有資料時當成一筆「通知全員、誰都能取消」的集合顯示 |
| `<prefix>/overrides/<成員id>/<day>` | 卡片 id。後存的為準 |
| `<prefix>/expenses/<key>` | 新增的紀錄：`payer` 存成員 id、`forWhom` 存成員 id 陣列，另存 `names: { <成員id>: <當時的名字> }` |

記帳讀取相容：`payer`／`forWhom` 的值對得上成員 id 就當 id；對不上就當名字去找成員；再找不到就顯示 `names` 裡的名字或原字串。不搬舊資料。

   - 新增時付款人預設是我；分擔預設 = 付款人當天日卡的同行名單（套用換卡；當天有多張卡取聯集；日期不在行程內或沒分組 = 全員）。
   - 新紀錄存成員 id 與當時的名字（1.5）。讀取相容舊的名字紀錄。結算以成員為單位，同一人的新舊紀錄要合併計算。
   - 已刪除成員的舊帳仍顯示當時的名字，結算仍計入。
5. **收尾**：拿掉 `groupFeatureOn()` 閘門與對應測試；更新 PROGRESS.md；產生器 Firebase 教學若有提到單一集合的文字一併檢查。
