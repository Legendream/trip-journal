# 分組旅行：設計決策紀錄

> 對應 brief.md。畫面在 Claude Design 畫布「分組旅行」。2026-10-06 整理，持續更新。

## 1. 資料結構

```
成員 members        id、代號、頭像（真正的資料）
組別 groups         id、組名、成員 id 清單、順序（最多 3 組；只是名單的別名）
日卡 cards          日期、主題…、同行的人：成員 id 清單（空值 = 全員）
  活動 acts         同行的人：成員 id 清單（空值 = 沿用日卡）
集合 meetings       時間、備註、設定者、通知誰：成員 id 清單
記帳 expenses       沿用現有；分攤預設 = 付款人當天日卡的同行名單
換卡 overrides      某成員某日期改跟哪張卡（見第 4 節）
各自手機            我是誰（成員 id 或空值）、檢視（我的行程／全部）
判讀提醒            即時計算不儲存；只存「已略過」清單
```

- 日卡、活動、集合只存成員，不存組別。
- 顯示時反推：名單 = 某組 → 組名標籤；全員 → 不加標籤；對不上 → 成員頭像。
- 改組別名單時，舊名單完全吻合的日卡一起改（顯示 G-9）。
- 成員 id（2026-10-06 定案）：產生器內部用 id；匯出時暫時維持用名字當 key，記帳 payer 不動。等 Firebase 資料路徑（PROGRESS.md 下一步 1）一起處理。

## 2. 組名標籤

- 主題深淺版，上限 3 組：實心（白字／深底）、外框（深字／白底）、淡底加框（深字／淡底）。
- 深色 = 主題主色混入 #1e0d12 35%。七款主題對比皆 ≥ 4.51:1。
- 「淡底不加框」保留給時間標籤，時間標籤不改。
- 第 3 組建立後隱藏「＋ 再加一組」，不加說明。
- 標籤外觀只用來顯示狀態；選擇器裡的組名用一般按鈕／單選，不用標籤外觀。
- 標籤字級需跟著 App 字體設定（標準／大／特大）放大。

## 3. 產生器

- D1（用 AI 整理）：填組別一次，寫進提示詞。
- 步驟 2「各組成員」：有組別時收成摘要＋編輯；三條匯入路線共用。
- 日卡只看不填：點標籤（含全員卡的虛線人形鈕）才打開選擇器。
- 選擇器為單選：全員／跟這天一樣（活動）、各組（附成員頭像）、自己選（展開成員）。選中項由名單反推。
- 同一天加卡「這天分頭行動」、合併「這天一起行動」。
- 合併卡片、刪除組別都不跳確認視窗，改用產生器既有的復原提示：「已合併 {日期} 的卡」（G-15）、「已刪除「{組名}」」（沿用既有格式）。

## 4. App 換卡（旅途中自己跳組）

- 只在同一天有兩張以上卡時出現；沒分組的行程不受影響（規則 7）。
- 「我的行程」裡那天卡片的組名標籤可點 → 「這天跟誰走？」→ 選一張卡。
- App 只能換整張卡；活動層級的調整回產生器處理。

| | 基本版（無 Firebase） | 進階版（Firebase） |
|---|---|---|
| 存放 | 只存在自己手機 | Firebase 同步 |
| 誰看得到 | 只有自己的「我的行程」 | 所有人的「全部」 |
| 影響 | 只有顯示 | 也影響「通知誰」、記帳分攤預設 |
| 提示 | 顯示「只有這支手機會換」 | 無 |
| 衝突 | 無 | 後存的為準 |

## 7. D4、D5、D6 取捨說明

**D4 我的行程／全部切換放哪**
- 考慮過：放在頭部、放在下方導覽列、放在行程分頁頂部。
- 選擇：行程分頁頂部，跟著內容捲走，外觀沿用清單分頁的子分頁按鈕；右側頭像鈕回到「你是誰」。
- 理由：頭部固定，加一列會壓縮可捲動範圍；導覽列不能動（不新增分頁）。

**D5 會合日卡**
- 考慮過：左右兩欄分組、卡內加「各組抵達」小標、只用組名標籤。
- 選擇：只用組名標籤，活動照時間排序。
- 理由：390pt 寬切兩欄太擠；加小標違反「不加句子」；照時間排，最後一筆帶標籤的抵達之後，第一筆沒標籤的活動自然就是會合點。

**D6 同一天兩張日卡**
- 考慮過：左右並列、左右滑動切換、上下堆疊。
- 選擇：上下堆疊；同日卡片間距 4px、內側圓角縮小，看起來是一組；不同日期維持 10px。
- 理由：滑動會藏起另一組，違背「全部」的目的；並列太窄。
