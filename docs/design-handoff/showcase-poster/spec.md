# 行程海報 v2 規格（給 drawShowcaseCanvas 換值用）

畫布 720×1280，輸出 ×2。手機全螢幕約 ×0.54（「pt」欄為換算值）。數值皆為畫布 px。
設計稿：Claude Design 畫布「行程海報改版」。最右側的「主版元件」可切換 7 個範例、4 種主題色與照片位置，其 `renderVals()` 是本規則的參考實作。

## 1. 三個主要改動

- 文字不再直接壓在主題色上。背景改用「主題色加深」，白字對比保證 ≥ 9:1；主題原色只留在頂部 10px 色條與強調色。
- 字級放大 2 到 3 倍。最小字 22px（約 12pt），主要內文 28 到 48px。
- 三段式版面：上段標題群、中段清單、下段住宿與一句話貼齊 footer 上緣。

## 2. 色彩 token

```js
const INK = '#100c0f';
// mix = sRGB 0–255 各通道線性內插；contrast = WCAG 相對亮度對比
let k = 0.40;
while (Math.min(contrast('#fff', mix(A, INK, k)), contrast('#fff', mix(B, INK, k))) < 9) k += 0.05;
const bgTop = mix(A, INK, k), bgBot = mix(B, INK, k);      // 背景：y0 bgTop → y1280 bgBot 線性漸層
const brighter = lum(bgTop) > lum(bgBot) ? bgTop : bgBot;
let s = 0.30;
while (contrast(mix(B, '#fff', s), brighter) < 5.5) s += 0.05;
const acc = mix(B, '#fff', s);                              // DAY 字樣、D 編號、圓點、引號、「＋N」
```

| 用途 | 值 |
|---|---|
| 主要文字 | `#ffffff` |
| 次要文字 | `rgba(255,255,255,0.78)` |
| 分隔線 | `rgba(255,255,255,0.12)`，1px |
| footer 卡 | `rgba(255,255,255,0.08)` |
| 頂部色條 | y0 高 10，A → B 水平漸層（有照片版不畫） |

## 4. 座標

- 共用：左右邊界 48，內容寬 624。內容下限 `LIMIT = 1016`（footer 頂 − 40）。
- 單日・無照片：色條 y0。行程名稱 y64。DAY 列 y124 高 128。主題 y272。清單起點 = 主題底 + 44。底部群組從 LIMIT 往上排：一句話 → 間距 20 → 住宿。清單與底部群組至少相隔 40。
- 單日・有照片：照片 y0 高 P（≤ 4 景點 520；5–6 景點 440；≥ 7 景點 400）。照片底部 160px 疊漸層：透明 → 該 y 位置的背景色。DAY 列 y = P + 28。主題 y = P + 80。清單起點 = 主題底 + 32。底部群組間距 12；清單與底部群組至少相隔 32。
- 整趟：色條 y0。標題 y64。副標 y = 標題底 + 12。清單上緣 = 副標 y + 76，下緣 LIMIT。
  - ≤ 14 天（單欄）：列高依內容而定。每列 = 名稱行數 × 行高 ＋ 日期 28（若有）＋ 留白；留白 = min((可用高 − 內容總高) ÷ 天數, 上限)，上限 ≤ 9 天為 32、10–14 天為 36；每列留白至少 16，不夠就換下一級字級。
  - 15 天以上：兩欄，欄寬 296、欄距 32，直向排列（先排滿左欄），列高 = 可用高 ÷ ceil(天數 ÷ 2)。
  - 列與列之間畫 1px 分隔線（最後一列不畫）。

## 5. 內容多或少時

- 換行優先，截斷最後：景點與每日名稱都先允許換到第 2 行；字級由大到小試，採用第一個「每項最多 2 行時全部放得下」的。
- 景點清單放不下：最小字級仍放不下時，由上往下放，留最後一行寫「＋N 個景點」（acc 色、不畫圓點）。
- 整趟單欄放不下：最小字級、2 行仍放不下時，改成每天 1 行並截斷。
- 有照片時先縮照片：P 每次 −80，不低於 320；仍放不下才截斷清單。
- 第 2 行仍放不下：第 2 行尾加「…」（逐字 measureText）。住宿名稱維持單行截斷。
- 兩欄的現實限制：每行約 7 字，2 行約 14 字；23 天以上只剩 1 行約 7 字。長的每日名稱在長行程一定會被截，建議 App 輸入每日主題時提示「10 字以內較好讀」。
- 主題／旅程標題：最多 2 行、逐字換行。2 行放不下先換小一級，再放不下第 2 行尾加「…」。
- 一句話：最多 2 行。
- 沒有住宿也沒有一句話：清單下限直接用 LIMIT。
- 超過 30 天：顯示前 29 天，第 30 格寫「還有 N 天」（acc 色）。
- 內容很少：景點字級上限 48，不再放大；空白留在清單和住宿之間。

## 6. 照片配圖（只在單日版）

- 入口：單日模式下一個「＋ 加一張照片」按鈕；加了之後顯示縮圖、「換一張」「移除」和「照片位置」三選一。整趟模式整個區塊隱藏。
- 不上傳：`<input type="file" accept="image/*">` 讀進來直接 `drawImage`，不送伺服器、不存檔，重新整理後需重選。
- 裁切：cover 填滿 720 × P。照片比例（寬 ÷ 高）≤ 720 ÷ P 時上下裁切，按鈕為「上／中／下」；比照片框更寬時左右裁切，按鈕為「左／中／右」。
- 焦點：上／左 = 0，中 = 0.5（預設），下／右 = 1。裁切起點 = (縮放後長邊 − 框的長邊) × 焦點。存比例不存像素，P 改變時仍對得準。
- 不做：拖曳、縮放、旋轉、濾鏡。等使用者回饋再評估。
- 設計稿：畫布「照片配圖（單日版限定）」一區，位置按鈕可以點。

## 7. 實作備註

- 設計稿的換行與截斷用字元寬度估算，實作請用 `ctx.measureText`，會有幾 px 差異。
- 表中「行高」是文字框高度；canvas 用 `textBaseline = 'middle'`、`y = 框頂 + 行高 ÷ 2` 最接近設計稿。
- 字重 800 / 900 在 PingFang TC 會對應到 Semibold 或 Heavy，以 iOS 實際渲染為準。
- 待確認：部分手機的 IG 限動底部回覆列可能蓋到 footer，建議實機分享一次再決定 QR 是否上移。
